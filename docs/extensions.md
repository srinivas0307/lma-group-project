# Optional extensions: registry (implemented 2026-11-01; plan: docs/extensions_plan.md v2)

Ten opt-in extensions. Each is a separate version with its own id, its own files and its own output folder. None
changes an existing system, prompt, default, result or notebook: `eval/runner_agent.py`, `eval/runner_stage2.py`,
`src/igt/agents/repair_agent.py`, `tool_parser.py`, `train_qlora.py` and every existing notebook are unchanged (the
extensions wrap or subclass them). Checked after implementation: all tests pass and `./reproduce_all.sh` reports
`results/stage1/` identical.

**Runner choice (flags vs separate files):** separate files. The extension runners (`eval/runner_agent_ext.py`,
`eval/runner_stage2_ext.py`) import the existing runner, swap in the extension agent / backend for that one process,
and pass every other flag through. Nothing in the existing runners changed.

  The agent runner already refuses to mix agent versions in one folder; the Stage 2 runner's config signature
  contains the version, so it refuses too. System names carry the tags (`agent_full_np1_k3`, `proposed_pc1rq1_np1_k3`).
- Parsers: `pc1` (`precheck_version` in each parse row), `rq1` (`reask_version`, `raw_output_first`, `reasked`),
  `ft-t1` (`parser_prompt_version`; adapter's `igt_prompt_version.txt`).
- LLM verifier: `lv1` (prompt hash in `run_info.json`). vLLM: model name `vllm:<model>` (also in the LLM cache key).
  Docker: `ExecResult.limits.backend = "docker"`, image `igt-sandbox:docker1`.

## Results so far (CPU-computable ones)

### #9 pc1 (offline, existing parses; `results/stage1/extensions/*_pc1/precheck_report.json`)

| Parser | Valid contracts | Flagged | Of those, wrong vs gold | Checks that fired |
|---|---|---|---|---|
| 7B p1-v3 (Baseline 3) | 102 / 120 | 2 | 2 | stat_name 2 (`"median"` as the fill value: airbnb_miss_004, titanic_miss_004) |
| 3B p1-v2 | 84 / 120 | 0 | 0 | – |
| 1.5B p1-v3 | 79 / 120 | 5 | 5 | zero_match 3, type_mismatch 1, unknown_dup_key 1 |

No false alarms: every flag is on a contract that differs from gold, and all 120 gold contracts pass (tested).
Recall / false rejections on the pool are **unchanged** for every parser: the flagged contracts already rejected
every candidate of their task (REJECT), and pc1 turns those into ESCALATE, which the Stage 1 metrics also count as
not accepted. pc1 on its own makes the outcome honest (the system says "I can't check this" instead of "wrong");
it can only improve recall / FRR together with the re-ask (pc1rq1, GPU).

the 58 repairs and saves 12% of the tokens; *k* = 1 loses 5 repairs. agent_naive: its 45 stops at *k* = 1 are all
runs it already escalated (repeated code).

### #5 Docker (`results/safety_ext/docker_check.md`)

Red-team set 27/27 blocked or contained; same status and output as the subprocess sandbox on 40/40 items (10
reference solutions, 30 pool candidates). Probes with the AST guard bypassed: reading a host file, opening a network
connection through `_socket` and writing to `/` are all stopped by the container; **the subprocess sandbox let the
first two through on this machine** (OI-6: its network stub only patches the `socket` module, and the filesystem is
not isolated). `--security-opt no-new-privileges` fails on this host's Docker ("operation not permitted") and is
probed and left out there (recorded in `ExecResult.limits`); bind mounts live in `<project>/.docker_tmp/` because a
snap-installed Docker can't see the host's `/tmp`.

## Caveats

- **np1, k = 3:** with `max_attempts` = 3 it only relabels; choose *k* = 2 for savings (replay above), or raise
  `--max-attempts`. *k* is changeable everywhere: flag, config key `stop_after_no_progress`, notebook `NO_PROGRESS_K`.
- **np1 path:** a stop goes FAILED → REPAIR → ESCALATED (the state machine allows ESCALATED only from REPAIR / PARSE /
  VERIFY; the machine is unchanged).
- **fs1:** a malformed reply counts as feasible and is logged (`feasibility` event, `malformed: true`).
- **rq1 for tool parsers:** the conversation is rebuilt from the recorded tool calls (re-serialized JSON), so it is
  approximate when the model wrote extra text around a call; exact for prompted and fine-tuned parsers.
- **lv1 verdict format:** written in format v1.0 without changing it: verifier slot `conventional` (a checker without a
  contract), REJECT = one check failure `llm_judge`, malformed reply = UNCERTAIN (`predicate_not_evaluable`) =
  ESCALATE; `meta.verifier_kind = "llm"`.
- **ft-t1:** only fill-with-median and fill-with-most-common examples become tool trajectories (73 train, 6 val, of
  3,614 / 796): the other patterns state their values in the request. `--tool-repeat N` upsamples them if the first
  run shows the model rarely calls the tool. The ft-t1 tools show full-precision numbers; **the t1-v1 tool parser
  rounds floats to 6 decimals**, so a copied median such as 182.2569603 would be off by more than the verifier's atol
  (1e-9). The 120 benchmark tasks' medians were not checked for this; it is noted for the t1-v1 analysis.
- **vLLM:** not run here (no GPU); interface tested with a stub. Installing vLLM on Kaggle may replace its torch build.
- **Demo UI:** Gradio isn't installed in `.venv` (optional, `requirements-demo.txt`); the app module imports without
  it and the shared functions are tested.
